Specificatoin of Video/Audio Encoder definition format for skyerip. Version 0.0.1-draft1. 2026-08-01 20:42 CEST
File extension: .sred



$INPUT *MUST* be provided by the user to place the input, otherwise it is assumed that the encoder reads from stdin BY DEFAULT WITHOUT ANY ADDITIONAL INPUT

output is always placed at the very end.

WARNING: IN-FILE COMMENTS WILL RESULT IN UNDEFINED BEHAVIOUR. unless placed on a new line after EOF.

Contents:
"sred" string to specify that the file is a skyerip encoder definition file, this will be checked by the program.
Version number in format "[major].[minor].[patch][indicator]", ended by \n. [indicator] is one charater reserved for specification version types, a - alpha, r - release.
path to encoder, ended by \n (For ease of implementation AND readability)
additional switches required for input to be read from STDIN
additional switch required for output (if none then '\n' shall be there)
list of switches in format (read struct sw in defines.h, one switch per line, types: 0 - NOTHING, 1 - int/double (int = den=1, double calculated into a string when starting encode), 2 - string (WARNING: WON'T BE CHECKED FURTHER),3 - multivar (also won't be checked, but will be filled out using template instead of being presumed user-specified static) ): "name,multi,mult_vars,type,min,max,den"
EOF

Example:
sred
0.0.1a
/usr/bin/x265
-i -

crf,0,,1,0,204,4
preset,0,,1,0,9,1
no-open-gop,0,,1,0,1,1
keyint,0,,1,1,9999,1
gop-lookahead,0,,1,1,240,1
rc-lookahead,0,,1,0,250,1
hme,0,,1,0,1,1
hme-search,1,"$hme1,$hme2,$hme3",3,,,
hme1,0,,1,0,7,1
hme2,0,,1,0,7,1
hme3,0,,1,0,7,1
strong-intra-smoothing,0,,1,0,1,1
rect,0,,1,0,1,1
aq-mode,0,,1,0,4,1
refine-mv,0,,1,0,3,1
rd-refine,0,,1,0,1,1
EOF
